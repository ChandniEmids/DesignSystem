Spacing
8px grid, primitive scale tokens, and semantic layout roles

All spacing in ClearPath FDO is derived from an 8px base grid. Every margin, padding, and gap value must be a multiple of 8px. Semantic roles then map those steps to specific layout contexts — keeping spacing decisions consistent and predictable across the UI.

8px Grid
Every spacing value is a multiple of 8. Non-multiples (6px, 10px, 14px) are never used.
Primitive → Role
Raw scale values (--space-1…8) are mapped to semantic roles (--space-card, --space-page-x) for components.
Predictability
Consistent rhythm makes layouts scannable. Adjacent elements share the same spatial logic.
No Eyeballing
Spacing decisions are never visual guesses. Every gap traces back to a defined token step.

Semantic Tokens

Role-based aliases that map scale steps to layout contexts. Components reference these — never the raw scale tokens.

Token Maps to Value Usage
Layout
--space-page-x var(--space-4) 32px Horizontal padding on main content area
--space-page-top var(--space-5) 40px Top padding below fixed header
--space-section var(--space-8) 64px Vertical gap between page sections
Components
--space-card var(--space-3) 24px Internal padding for cards and panels
--space-form-gap var(--space-2) 16px Gap between form fields
--space-inline var(--space-1) 8px Inline gap between icon and text label
Usage Rules
Multiples Only
Always use multiples of 8

Permitted: 8, 16, 24, 32, 40, 48, 56, 64px. Forbidden: 6, 10, 12, 14, 18, 20, 28px — these break the grid rhythm.

Semantic Over Primitive
Reference roles, not steps

Use --space-card rather than --space-3 in component CSS so intent is readable.

No Raw Values
Never hardcode pixel values

Never write padding: 24px in a component. Always reference var(--space-card) or the appropriate token.

Scale Up, Not Out
Choose the next step up

When unsure between two steps, choose the larger one. Generous spacing reads as intentional; tight spacing reads as cramped.

Dos & Don'ts
Do
  • Use gap: var(--space-inline) for icon-to-label gaps
  • Use padding: var(--space-card) for all card bodies
  • Use padding: 0 var(--space-page-x) for page-level horizontal gutters
  • Keep density consistent within a section — all cards use the same padding step
Don't
  • Don't use margin: 12px or any non-grid value
  • Don't mix semantic and primitive tokens in the same property
  • Don't add extra spacing inside components to compensate for layout issues — fix the layout
  • Don't use padding to create visual dividers — use a border or a background change
CSS Custom Properties

All spacing tokens live in global.css — Layer 1 for the scale, Layer 2 for semantic roles.

Layer 1 — Scale Primitives
/* global.css — Layer 1: Spacing */
:root {
  --space-1: 8px;
  --space-2: 16px;
  --space-3: 24px;
  --space-4: 32px;
  --space-5: 40px;
  --space-6: 48px;
  --space-7: 56px;
  --space-8: 64px;
}
Layer 2 — Semantic Roles
/* global.css — Layer 2: Spacing Semantics */
:root {
  /* Layout */
  --space-page-x:   var(--space-4);  /* 32px — horizontal page padding */
  --space-page-top: var(--space-5);  /* 40px — top content padding */
  --space-section:  var(--space-8);  /* 64px — section vertical gap */

  /* Components */
  --space-card:     var(--space-3);  /* 24px — card internal padding */
  --space-form-gap: var(--space-2);  /* 16px — gap between form fields */
  --space-inline:   var(--space-1);  /*  8px — icon + text gap */
}
Example Usage
/* Card component */
.appointment-card {
  padding: var(--space-card);
  gap: var(--space-inline);
}

/* Page main content */
#appMain {
  padding: var(--space-page-top) var(--space-page-x);
}

/* Form field stack */
.form-stack {
  display: flex;
  flex-direction: column;
  gap: var(--space-form-gap);
}
