Color System
Primitive palette, semantic tokens, and appointment type colors

ClearPath FDO uses a two-layer color model: primitive colors define the raw palette, and semantic tokens assign those primitives to roles in the UI. Components always reference semantic tokens — never raw hex values — so theming and iteration remain contained.

Consistency
Every color decision traces back to a named token. No one-off hex values in components.
Accessibility
All text-on-background pairs meet WCAG AA contrast (4.5:1 for body, 3:1 for large text).
Minimalism
The palette is intentionally small. New colors require explicit justification before being added.
Clinical Trust
Healthcare context demands restraint. Saturated and playful colors are reserved for status only.

Usage Guidelines
Text
  • Use color.text.primary for all body copy, headings, and form labels.
  • Use color.text.secondary for supporting captions, section headers, and descriptions.
  • Use color.text.muted only for placeholders and truly de-emphasized metadata.
Interactive & Brand
  • Use color.brand.blue for nav active state, focus rings, and inline links.
  • Use color.brand.cta only for the primary action button and logo icon.
  • Use color.brand.path for teal brand accent: avatars, live dots, stepper progress.
Surfaces & Borders
  • Use color.surface.1 for all content surfaces — cards, modals, side panels, dropdowns.
  • Use color.border.subtle for structural lines (section dividers, table row separators).
  • Use color.border.input only for form control outlines.
Status Colors
  • Use semantic groups (error, success, warning, info) only for status communication — not decoration.
  • Never repurpose primary or secondary colors to convey status.
  • Appointment type colors are a separate system — do not mix with UI status colors.
Appointment Type Colors

A dedicated token set for identifying appointment types visually. These colors exist solely to distinguish appointment categories — they carry no semantic meaning beyond type identification.

Medical Test color.appointment.medicaltest #1E293B #F1F5F9
Strict Usage Rules
  • Use only to identify appointment type on cards, tags, and detail panels.
  • Never use for UI actions, status indicators, alerts, or any non-appointment context.
  • Cannot be reused elsewhere in the UI — not as hover states, borders, or decorative fills.
  • Do not mix with semantic tokens (error, success, warning, info) — they serve different purposes.
